**Machine Consciousness** is the deterministic non-LLM cognitive and orchestration substrate. **Agent Lee** is its Creator-facing identity. Model Hub is an optional specialist evidence, language and teaching provider. The lightweight three-model Qwen roster (Qwen3 0.6B, Qwen3 1.7B, Qwen3.5 0.8B) is a proposed support arrangement, NOT a replacement Machine Consciousness brain, autonomous workforce or independently authorized verification system.

This is consistent with original [universal employee contract](../../training/contracts/leeway-universal-employee-consciousness.v1.json) and [cross-repository integration v1](leeway-cross-repository-integration-v1.md), not a superseding constitution. The original Skill Orchestrator, Skill Factory, Capability Resilience, Parallel Workplane, Tool Gateway, Formula, Runtime, Device Bridge, independent Veritas, Receipt Authority, Continuum and Learning Ledger remain the only owning authorities for their operations.

Source code implemented in [model-support-convergence.mjs](../../training/reference/model-support-convergence.mjs) and tests is a **pure reference candidate**. It can *actually compute* bounded due-inspection states, normalize multiple source-referenced model critiques and produce a worker proposal object, but it does not schedule jobs, invoke a model, train weights, grant worker access, dispatch a host, independently verify anything or save a production receipt. Its optional model list never becomes a universal dependency of Machine Consciousness.

## Cooperative model team duties

1. **Watch and detect**: consume original Runtime/Bridge telemetry, owner-visible application outcomes, failed tasks, missing worker coverage and observability gaps from authorized data; present referenced observations and explicitly unverified claims.
2. **Collaborative critique**: Qwen3 0.6B may propose an intent/category, Qwen3 1.7B may explain candidate repair/skill atoms, and Qwen3.5 0.8B may inspect genuinely accessible screenshot evidence. Roles overlap and cross-review; no fixed one-model-per-app silo. No model has to be available for deterministic core behavior.
3. **Assess worker coverage**: search actual owned worker registry/capability graph first. Reuse existing workers before suggesting new. If coverage is missing, refer a candidate to ORIGINAL Skill Factory; it must qualify a native skill/adapter, never instantiate an arbitrary independent assistant.
4. **Handoff to Machine Consciousness**: return structured candidate evidence, assumptions, alternatives, skills/tools, design and acceptance tests. Machine Consciousness chooses the bounded work objective and original W02 Runtime execution path.
5. **Observe and teach back**: after actual bounded execution and independent post-gates, candidate patterns may be learned with proven source/custody through Continuum and Learning Ledger. Models may criticise future failures and suggest worker skill upgrades. They are not independent Veritas.
6. **Periodic review**: requested three-hour inspection cadence is a parameter to the EXISTING Runtime persistent workplane; it requires an actual registered job, permission, real data and time/availability policy. This source's due-calculation is not an actual scheduled background job.

## True execution path

`Creator/Agent Lee → Machine Consciousness (owner) → original Formula decision + Skill Orchestrator → original Runtime W02 workplane → original Tool Gateway/Device Bridge/qualified native worker → real post-state → independent Veritas → Receipt Authority → Continuum readback → Learning Ledger if eligible → Machine Consciousness response`.

Model advice enters Machine Consciousness **before** work selection or as a read-only post-execution critique. It cannot call a device, choose its own scope, create credentials, elevate a worker, finalize a receipt or claim that a task is complete. The original Runtime's own acceptance tests remain necessary. Keep denial, cancellation, interrupted host/reconnect and rollback as first-class outcomes. An absent LLM should not block native deterministic work where a qualified native worker already exists.

**Example — source to infographic:** Office Suites already owns source parsing and editable rendering; Model Hub reports unsupported chart claims and suggests additional validation. Machine Consciousness requests the existing Office skill, authorizes native Office renderer/worker through original Formula/Runtime, observes the resulting infographic, and asks independent Veritas to check provenance/post-state. Model Hub gets a compact critique and candidate skill-improvement case; it does not become the document renderer or execute that worker.

**Example — failed crawling:** Machine Consciousness sees repeated approved crawl-task failure with source facts and real usage metrics. It checks for an existing lawful site-fetching or browser capability. If missing, models can draft a bounded native crawler skill and negative tests; original Skill Factory qualifies source rights, robots/access policy, rate limits, allowed URLs and security. Original Runtime/Bridge runs it only after authentication, scope and Veritas pre-gate. The resulting worker is bound to one shared consciousness and existing permissions.

## What the 16B ambition can and cannot mean

16-billion-parameter-style **performance** is an empirical target for selected tasks, not a measurable parameter count of the deterministic substrate, proof of subjective life or a claim that three smaller models have inherited a 16B model's internal knowledge. Define a held-out task suite across:
- supported Agent Lee conversation, voice continuity and source-grounded Office infographic quality;
- IDE code repair with runnable tests and correct refusals;
- CRM follow-up consent, ERP-to-Logistics reconciliation and safe route intelligence;
- visual UI inspection when a real qualified image adapter exists;
- worker recovery, multi-step execution, permission denial, autonomy boundaries, tool reuse, tokens per model task, RAM/CPU usage, latency and failures.

Compare a frozen prior Machine Consciousness+skills baseline and, separately, a suitable 16B reference on the **same** tasks, reference materials, permissions, contexts and hardware constraints. Report percentage of accepted outcomes, regressions, cost/latency and rights separately; never report a fictitious "16B-equivalent intelligence score."
